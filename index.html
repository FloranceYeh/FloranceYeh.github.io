给现有 Web 项目套上 Tauri 外壳

Tauri 适合把已经可以在浏览器中运行的前端项目，打包成体积更小的桌面应用。它不会要求你把现有项目重写成某种框架：React、Vue、Svelte、原生 HTML/JavaScript，以及只要能通过 HTTP 服务运行的其他前端项目，都可以作为 Tauri 的界面层。

本文以一个已有的 Vite 前端项目为例，介绍如何在不改动原前端子模块的前提下接入 Tauri，并在最后介绍一个可选的进阶功能：隐藏系统标题栏后，通过初始化脚本注入自定义标题控件。

使用 Astro 作为 Tauri 的前端

Tauri 通常被描述为“Rust 后端加 Web 前端”的应用框架。它并不要求前端一定使用 React、Vue 或 Svelte，只要前端最终能够提供一个静态目录，或者在开发阶段启动一个兼容的开发服务器，就可以作为 Tauri 的界面。

Astro 很适合内容型应用：页面可以在构建阶段生成，Markdown 可以直接作为内容源，最终产物不需要 Node.js 运行时。本文以一个已经存在的 Tauri 2 项目为例，说明如何把 Astro 接入其中，并继续支持桌面端和 Android 调试。

AHNUMCL 开发记录
开发记录 2026/9/8

AHNUMCL 开发记录

项目地址：https://github.com/ahnumc/AHNUMCL

引用

AHNUMCL 不是重新发明一个 Minecraft 启动器，而是在成熟的上游项目基础上，逐步建立自己的品牌、服务和发行节奏。

暑假，我加入了 AHNUMC 社群。AHNUMC 是一个由安徽师范大学学生自发组建的 Minecraft 社群，大家因为游戏聚在一起，也尝试为社群成员提供服务器、账号、整合包和交流内容。AHNUMCL 正是在这样的背景下开始开发的：它不是为了单纯制作一个启动器，而是希望把社群已有的服务更方便地交给玩家使用，降低进入服务器、安装客户端和获取相关信息的门槛。

因此，项目中的 AHNUMC 登录、服务器列表、客户端整合包、新闻接口和多人联机功能，都不是孤立的演示功能，而是围绕社群玩家的实际需求逐步加入的。启动器既是一个桌面软件，也是 AHNUMC 社群服务玩家的一部分。

这段开发过程最有意思的地方，不是某一个单独的页面，而是一个分支项目怎样从“改几个名称”逐渐变成可以独立发布、独立维护的桌面应用。
